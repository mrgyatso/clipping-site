# CLAUDE.md — shared rules for this repo

Rules for **any** coding agent working on this project: Claude Code, Codex, Cursor,
whatever. Two people share this repo, each with their own agent. These rules exist
so neither agent's work lands as a painful merge on the other's desk.

Read this file before your first edit in a session. If you are about to break one
of these rules on purpose, say so out loud first and get a human to agree.

---

## 1. The repo

- **Canonical remote:** `git@github.com:mrgyatso/clipping-site.git` (`origin`).
  This is the single source of truth. Forks exist, but work lands here.
- **Stack:** Next.js 16 (App Router, Turbopack), React 19, TypeScript strict.
- **Deploy target:** Vercel.
- `main` is the shipping branch. **Never commit directly to `main`.**

## 2. Ownership — do not touch another person's zone

Each owner can claim files or directories here. If a path is claimed by someone
else, **do not edit it**. Open a PR comment or leave a note instead. If your task
seems to require editing a claimed path, stop and ask the human.

| Zone | Owner | Notes |
|---|---|---|
| `data/site.ts` — pricing, FAQs, copy constants | **Zack** | Pricing is a business decision, not an implementation detail. |
| `app/terms/`, `app/privacy/` | **Zack** | Legally binding language. Never reword without explicit sign-off. |
| `data/clips.links.txt`, `scripts/fetch-clips.mjs` | **Zack** | The clip pipeline. |
| _(unclaimed — add yours here)_ | Jonathan | |

**To claim a zone:** add a row, commit it on its own, and tell the other person.
Claims are advisory to humans and binding on agents.

## 3. Git workflow — the important part

**Branch naming:** `feat/…`, `fix/…`, `copy/…`, `chore/…`. Keep them short.

**Every change goes through a branch and a PR.** No exceptions, no direct pushes
to `main`.

```bash
git checkout main
git pull --rebase origin main        # always rebase, never merge, when syncing
git checkout -b feat/your-thing
# …work…
git push -u origin feat/your-thing
gh pr create --fill
```

**Keeping a branch current:** rebase onto `main`, do not merge `main` into your
branch. Merge commits from `main` into feature branches turn the history into a
thicket and make the other person's rebase painful.

```bash
git fetch origin
git rebase origin/main
```

**Never force-push a branch the other person may have checked out.** If you must
rewrite history on a shared branch, use `--force-with-lease` and tell them first.

**Commit messages:** `<type>: <imperative description>` — `feat:`, `fix:`,
`copy:`, `refactor:`, `chore:`. One logical change per commit. A commit that
touches pricing copy *and* refactors a component is two commits.

**Before you push, all three must pass.** A red branch wastes the other person's
review time:

```bash
npm run lint        # eslint — 0 errors
npm run typecheck   # tsc --noEmit — 0 errors
npm run build       # next build — must succeed
```

## 4. Files that cause phantom merge conflicts

These will burn you. Treat them carefully.

- **`next-env.d.ts`** — `next dev` and `next build` rewrite this file
  (`.next/types` vs `.next/dev/types`) depending on which ran last. **Never
  commit a change to it.** If it shows up in `git status`, `git checkout --` it.
- **`data/clips.generated.json`** — generated by `npm run clips`. Do not
  hand-edit. If you need a different handle or view count, that is a code change
  in the pipeline, not a JSON edit.
- **`public/media/clips/*.mp4`, `public/media/posters/*.jpg`** — binary, and git
  cannot merge binaries. Only the clip pipeline writes these. If both of you add
  clips at once, whoever rebases second re-runs `npm run clips`.
- **`package-lock.json`** — if it conflicts, do not hand-merge. Take `main`'s
  version and re-run `npm install`.

## 5. Design system rules

- **All colour goes through the CSS custom properties in `:root`** in
  `app/globals.css`. Never hardcode a hex outside that block. The palette
  switcher works by overriding those tokens under `[data-palette="…"]`, so a
  hardcoded colour is invisible to it and silently breaks theming.
- If you add a token, add it to **every** palette block, not just `:root`.
- Accent usage is split deliberately: `--orange` on the dark ink bands,
  `--orange-ink` on paper. Do not collapse them — a light accent on paper fails
  contrast.
- Content is revealed on scroll via `.reveal` / `.reveal.in`. Anything hidden by
  CSS **must** have something that un-hides it, or the page ships blank. See the
  failsafe in `app/layout.tsx`.

## 6. Copy and claims

- **Never invent metrics, view counts, testimonials, or case studies.** Every
  number on the site must trace to something real. The clip wall reads its view
  counts off the live posts for exactly this reason.
- Pricing is **$4 per 1,000 valid verified views, $1,000 minimum budget**
  (250,000 views at the minimum). It is a rate, not a package. If you find copy
  that contradicts this, flag it — do not silently "fix" it in one place.

## 7. Working with the clip wall

The homepage carousel is driven by a link list, not by hand-managed files.

```bash
# 1. add TikTok / YouTube Shorts / Instagram Reels URLs, one per line
$EDITOR data/clips.links.txt

# 2. download, transcode, and read live view counts
npm run clips

# 3. re-read view counts for clips already downloaded
npm run clips -- --refresh
```

Requires `yt-dlp` and `ffmpeg` on PATH (`brew install yt-dlp ffmpeg`). Clips
already on disk are skipped, so re-running is cheap. A dead or private link is
skipped with a warning rather than failing the run.

## 8. General conduct

- **Surgical changes.** Every changed line should trace to the task. Do not
  reformat, rename, or "improve" adjacent code you were not asked to touch.
- **Match the surrounding style** even where you would do it differently.
- Do not add dependencies without saying why. This site ships almost none.
- Do not add speculative abstraction, config, or error handling for cases that
  cannot happen.
- If the task is ambiguous or you think the request is wrong, **say so before
  building it**, not after.
